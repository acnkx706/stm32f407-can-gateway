## 三、推算的平均帧率

```
时长         = 09:49 - 23:41 ≈ 9 小时 08 分 = 32,880 秒
接收帧数     = 684,208
平均帧率     = 684,208 / 32,880 ≈ 20.8 帧/秒
```

**F103 的设计上报速率**：0x101（遥测）10 Hz + 0x102（状态）10 Hz = **20 帧/秒**。

**实测 20.8 帧/秒**，比设计的 20 略高——差值来自期间手工发的 UDS 测试帧。

**这个数字对上，说明：**
1. F103 一整夜都在按 10 Hz 正常采集上报，没有卡死、没有降频
2. CAN 总线上没有因为负载过高而丢帧
3. F407 的接收中断没有漏帧

## 四、为什么这不算正式验收

**必须说清楚，否则数字会被误用。**

| 缺口 | 说明 |
|---|---|
| **没有独立的时间戳记录** | 起点和终点的时间是我从会话记录的采样时刻推的，不是设备自己记的 |
| **中途有手工干预** | 期间跑过几次测试（`rf` 的增量里有一部分是测试帧） |
| **没有中间采样** | 只有起点和终点两个点，看不出有没有"跑三小时好、第四小时坏、第五小时又好了" |
| **没有温湿度环境记录** | 室温变化会影响晶振漂移和 SD 卡速度，但没记 |
| **不是 72 小时** | 业界长稳通常跑 72 小时，9 小时只能叫"短稳" |
| **固件不是最终版** | 观察的是 CAN 流控版；UI 改造版是 2026-11-24 11:15 才烧的 |

**所以这份记录的正确定位是：一次"没有发现问题"的短时观察，可以作为正式验收的前置检查。**

## 五、`to` 那一项要盯住

`to`（流控等待超时）是所有指标里唯一在涨的：

```
起点 14 次 / 9 小时 → 终点 15 次
```

**含义**：F407 发完一帧连续帧后等 F103 的流控帧（FC），100 ms 内没等到，就降级为"继续发"并计数。

**为什么会超时**（目前的分析，未证实）：

- F103 正在做 W25Q64 扇区擦除（45~400 ms），中断响应被拖慢
- 或者 F103 的 CAN 发送邮箱被 0x101/0x102 占满，FC 帧发不出去

**为什么没造成故障**：超时后 F407 降级继续发，F103 的 `s_bs_left` 只用于节流，丢了 FC 不影响它把包收完。所以数据是对的，只是"该等的没等到"。

**要不要修**：暂时不用。**一夜只发生 1 次**，且不影响正确性。但如果是正式产品，这属于"可观测的异常"，应该查到底。

## 六、下次做正式长稳测试的建议

如果要做一份能写进简历的 72 小时记录，至少要补这些：

### 6.1 设备侧自记（关键）

现在所有数据都靠 PC 抓，PC 一重启就断。建议在 F407 上加一条**每小时自动打印一行**：

```c
/* 每小时打一行，方便事后对齐时间轴 */
if ((HAL_GetTick() - last_hour) >= 3600000u)
{
    last_hour = HAL_GetTick();
    printf("[HOUR] t=%lu rf=%lu ack=%lu drop=%lu to=%lu wmax=%lu\r\n",
           (unsigned long)(HAL_GetTick() / 1000u),
           (unsigned long)g_can_rx_frames, (unsigned long)g_can_ack_err,
           (unsigned long)g_fwd_can_drop, (unsigned long)g_fwd_isotp_fc_to,
           (unsigned long)g_fwd_isotp_wait_max);
}
```

**这样即使 PC 断了，串口日志（或 SD 卡）里也有完整时间轴。**

### 6.2 PC 侧持续采集

写一个 `longrun.py`：
- 每 60 秒读一次 `Q` 和 `/data`
- 追加写 CSV：`时间, rf, ack, drop, bad, to, wmax, 温度, 湿度, 气压`
- 同时记录 PC 时间，事后能画曲线

### 6.3 判定标准（事先定好，不能事后找理由）

| 指标 | 通过标准 |
|---|---|
| 运行时长 | ≥ 72 小时 |
| ACK 错误 | 全程 0 |
| 转发丢弃 | 全程 0 |
| 帧率 | 每小时采样，偏离 20 帧/秒 不超过 5% |
| 流控超时 | ≤ 10 次 / 72 小时 |
| 数值漂移 | 温度/湿度/气压与参考表一致，无跳变 |
| 无重启 | 启动横幅只出现 1 次 |

### 6.4 环境记录

- 室温（每小时记一次，或者用 F103 自己的温度做参考）
- 供电方式（USB 还是外部电源）
- 网线/杜邦线是否被碰过（这是最容易出问题的环节）
